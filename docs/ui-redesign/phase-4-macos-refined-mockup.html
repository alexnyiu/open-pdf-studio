TraceMonkey: a fast tracing VM

Tracing virtual machines can optimize frequently executed code by recording a path through the interpreter and compiling that path into native instructions.

Nested loops are difficult to optimize when the inner loop exits with a different branch or type combination. The monitor records enough context to make the transition explicit.

1. Introduction

A trace is a linear sequence of operations collected from a hot path. When the path is stable, the compiled trace can be reused and side exits remain available for unusual inputs.

This paper describes a compact architecture for recording, compiling, and executing traces while keeping the document of the program readable for review.

We implemented the system in a JavaScript interpreter and measured consistent improvements across a set of small industry benchmarks.

For each loop edge the monitor decides whether to continue recording, enter a compiled trace, or return to interpretation. These states form a small state machine.

2. Overview

The interpreter begins in a bytecode state. After a loop becomes hot, the monitor records a trace and hands it to the compiler. The compiled path can then execute directly.

Our approach keeps the common case fast without requiring the compiler to understand every possible path through the program.
